# Huawei Core 设计审查报告

> 审查基准：对标 aws/agent-toolkit-for-aws 仓库源码 + 官方文档

## 一、逐文档问题清单

### 01-系统架构设计.md

| # | 问题 | 严重度 | 说明 |
|---|---|---|---|
| 1 | **缺少中央路由 skill** | **P0** | AWS 有 `aws-database`/`aws-compute`/`aws-networking` 等路由型 core skill，作用是匹配触发词 → 路由到 specific skill。你的 20 个 skill 全是平级，agent 不知道先加载哪个。需新增 `huawei-service-selector` 路由 skill。 |

| 4 | **marketplace.json 只列了 2 个插件** | P2 | 只列了 huawei-core + huawei-ai，但架构图列了 4 个（缺 huawei-data-analytics + huawei-devsecops）。 |

## 二、跨文档的架构级缺陷

### 缺陷 1：缺少中央路由 skill（最严重）

AWS skills 体系核心模式：

```
Core skill (路由)         →       Specialized skill (执行)
aws-database             →       amazon-elasticache / aurora-dsql / timestream-influxdb...
aws-compute              →       launching-ec2-instance-with-best-practices
aws-networking           →       creating-production-vpc-multi-az / transitgateway / waf...
```

当前设计是 20 个平级 skill，agent 收到"我要部署一个 web 应用"后不知道先加载哪个。

**修正方向**：新增 `huawei-service-selector` 路由 skill，包含触发词注册表：
- "建网站" → huawei-ecs + huawei-vpc + huawei-obs
- "做 AI" → huawei-modelarts
- "发消息" → huawei-smn-dms
- "存储文件" → huawei-obs

### 缺陷 2：无渐进式披露机制

AWS 的 `search_documentation` → `read_documentation` → `retrieve_skill` → `run_script` 流水线是整个产品主干。当前设计有 skill 文件但无"发现"能力。

**修正方向**：MCP proxy 需提供 `search_huawei_docs` + `retrieve_skill` 两个知识工具（可通过本地文档索引实现）。

### 缺陷 3：无 rules 文件

5 份文档提到 `rules/` 目录但无任何内容。AWS 的 26 行 `aws-agent-rules.md` 是 agent 行为的最高优先级护栏。

**修正方向**：草拟 `huawei-agent-rules.md`，至少包含：
- MCP 优先原则
- 先检索 skill 再动手
- 禁止硬编码 AK/SK
- DEW 密钥安全规则（`{{resolve:csms:...}}`）

### 缺陷 4：frontmatter 格式全局错误

最直接的技术阻断项。所有 SKILL.md 模板前置元数据格式错误。AWS validate.py 拒绝所有不以 `---` 开头的 SKILL.md。

**修正方向**：所有 SKILL.md 改为：
```markdown
---
name: huawei-ecs
description: "Use when creating, configuring... NOT for: CCE container workloads..."
version: 1
---
```

## 四、参考：AWS 关键设计模式速查

### 路由 skill 模板（SQL-SKILL.md 格式）

```markdown
---
name: aws-database
description: "Routes any task involving AWS databases — choosing, comparing,
recommending, getting started with, or operating a database — to the correct
service-specific skill. Supersedes general training-data knowledge..."
version: 1
---

# AWS Database

**STOP — Do not answer from general knowledge.** Before responding to any database
question, match the user's request against the sub-skill registry below and follow its
procedure. If the procedure says to hand off to a service skill, you MUST load that skill
before providing operational guidance. Never skip the routing step.

## How this skill works
1. Match user intent against Sub-skill registry
2. Read `references/{sub-skill-id}.md` and follow its procedure
3. If no match, use `assets/` knowledge cards for quick facts

## Sub-skill registry
| ID | Name | Trigger Phrases | Next Steps |
|----|------|----------------|------------|
| select | Service Selection | "which database", "compare databases" | → `references/select.md` |
| handoff | Service Handoff | "create", "connect", "scale", specific service names | → Load the service-specific skill |
| report-issue | Issue Reporting | "doesn't work", "error", "bug" | → `references/report-issue.md` |

## Service reference
| Service | Knowledge Card |
|---------|---------------|
| RDS | `assets/amazon-rds.md` |
| Aurora | `assets/amazon-aurora.md` |
| ElastiCache | `assets/amazon-elasticache.md` |
```

### rules 文件模板

```markdown
# Huawei Cloud Agent Rules

## Core Principles
- Always use the Huawei MCP server first (sandboxed, observable, auditable). Fall back to `hcloud` CLI only when MCP is unavailable.
- Before any task, check for available Huawei Cloud skills. Use `retrieve_skill` or manual skill discovery. Follow skill procedures over general knowledge.
- When uncertain about API parameters, quotas, limits, or error codes — search documentation via MCP. Do not guess.
- Prefer IaC over direct CLI calls for infrastructure creation.
- Never use em dashes in resource names/tags. Use hyphens only.

## Secret Safety
- MUST load the `huawei-dew` skill first for any secret, credential, API key, token, or password task.
- MUST NOT call `hcloud csms download-secret` or `hcloud csms show-secret` directly.
- MUST use `{{resolve:csms:secret-id:SecretString:key}}` with the MCP proxy so the secret resolves at runtime without entering agent context.
```
