## 二、新的审查发现

### 2.1 SKILL.md 格式统一只做了一半（P0）

路由 skill（`huawei-service-selector`）的 SKILL.md 是正确的 YAML fenced 格式：

```markdown
---
name: huawei-service-selector
description: "Routes any task ..."
version: 1
---

# Huawei Cloud Service Selector

**STOP — Do not answer from general knowledge.**
```

但从第 168 行开始，**huawei-ecs、huawei-obs 等具体 service skill 仍然是旧格式**：

```markdown
name    huawei-ecs
description    Use when creating...
version    1
```

**必须将所有 service skill 模板改为 YAML fenced frontmatter。** 02-核心技能设计.md 的 huawei-ecs、huawei-obs 两段须重写。其余 6 个（iam/functiongraph/cce/modelarts/dew + 剩余 12 个）也要改为标准格式。

### 2.2 Service skill 缺 "STOP" 规则（P0）

路由 skill 有 `**STOP — Do not answer from general knowledge.**`。但具体 service skill（huawei-ecs / huawei-obs / ...）都没有。AWS 的 **每个** service skill 都以此开头。这是让 agent 在路由后仍然信任 skill 优先于模型知识的关键。

### 2.3 测试计划仍缺失（P0）

05-实施指南未添加测试/CI 校验里程碑。v1 审查要求的 P0 项。建议在 Phase 1 中增加：
- `tools/validate.py` — SKILL.md frontmatter + marketplace + manifest 格式校验
- `tools/sync-plugin-skills.py` — skills/ 目录与 plugins/ 副本一致性检查（若采用同步模式）

### 2.4 01-系统架构设计.md 第 34 行残留（P2）

```markdown
│   └── huawei-core/...后续扩展: .../      ← DevSecOps ...
```

旧文字残留，与同一行的"当前唯一插件"描述矛盾。
