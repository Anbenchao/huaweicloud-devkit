## 一、执行过程流水

### 阶段 1：安装插件（openopcode 集成）
1. 克隆仓库 → 移动到 `~/.agents/huaweicloud-agent-toolkit`
2. 按官方 `install-opencode-local.ps1` 逻辑安装：6 个 skills → `~/.config/opencode/skills/` 与项目级 `.agents/skills/`；1 个 command（huaweicloud-doctor）
3. 按 `integrations/opencode/opencode.json` 将 MCP（`node plugins/huaweicloud-core/src/mcp-server.mjs`）写入 `~/.config/opencode/opencode.jsonc`（改为绝对路径）
4. `npm test` 9/9 通过；`npm run validate` 通过；MCP server 冒烟测试通过（tools/list 返回 6 个工具）
5. 说明：本会话中 skills 与 MCP 工具为启动时注册，故测试期间通过直接驱动插件自带 MCP server（mcp-server.mjs，同一代码路径）执行

### 阶段 2：环境就绪
6. 插件工具 `huaweicloud_check_cli` 确认 hcloud 未安装（`installed: false`）
7. ⚠️ **缺口 G1**：插件只说"去安装 KooCLI"，无安装指引 → 用户授权后，自行查找官方文档（`support.huaweicloud.com/qs-hcli/`），从官方 OBS 下载 `huaweicloud-cli-linux-amd64.tar.gz` 安装到 `~/.local/bin/hcloud`（v7.2.12）
8. ⚠️ **缺口 G2**：插件不教凭证配置（`huaweicloud-cli-and-auth` 技能只写"请用户在对话外配置"，无命令、无字段说明、无 AK/SK 获取指引）→ 用户困惑"不会配"，自行查官方文档后指导用户：控制台→我的凭证→访问密钥→新增；`hcloud configure init` / `configure set --cli-access-key --cli-secret-key --cli-region`

## 五、建议记录（经验沉淀）

### 5.1 KooCLI 应该安装在哪里
- **Linux / WSL / macOS（推荐）**：装到用户目录 `~/.local/bin/hcloud`（本次采用），无需 sudo、不污染系统目录；把 `~/.local/bin` 加入 `~/.bashrc` 的 PATH。
  - 注意：opencode/agent 进程的 PATH 继承自启动它的 shell，插件 `spawn('hcloud')` 靠 PATH 找可执行文件；若 opencode 由桌面/服务启动，需确认 PATH 包含该目录（本次正是靠 bash 里 `export PATH="$HOME/.local/bin:$PATH"` 才让插件找到 hcloud）。
- **Windows 原生**：解压官方 `huaweicloud-cli-windows-amd64.zip` 到用户目录（如 `%USERPROFILE%\hcloud`）并加入用户 PATH；装 `C:\Program Files` 需要管理员权限，不建议。
- **CI/容器**：官方镜像 `cn-north-4-hdn-koocli.obs.cn-north-4.myhuaweicloud.com/cli/latest/` 直接拉取对应 tar.gz，解压即用。
- **插件层面建议**：① `huaweicloud_check_cli` 检测失败时，应返回官方下载地址 + 上述安装位置建议（现只返回"去安装"三字）；② 建议支持环境变量（如 `HCLOUD_BIN`）指定 hcloud 路径，避免 PATH 问题。

### 5.2 凭证配置
- AK/SK 在控制台「我的凭证 → 访问密钥」创建（SK 只显示一次，务必保存）。
- 配置用 `hcloud configure init`（交互式，SK 输入两次且匿名回显），凭证加密存于 `~/.hcloud/config.json`。
- Region 建议在创建实例的目标区域（本次 ap-southeast-3），但每条命令也可用 `--cli-region` 覆盖。

### 5.3 区域语义
- 用户说"新加坡"时应先查 ap-southeast-1 / ap-southeast-3；不确定参考实例位置时先问用户，不要全地域盲扫（G12）。

### 5.4 购买类写操作
- 先 `--dry_run=true` 预检再正式创建（本次流程，零成本防呆）；Windows 实例避免在命令行传 adminPass（会进 shell 历史），建议创建后控制台重置或使用随机密码。
